## 3. 数理モデル

### 3.1 記号

- 牌の種類は34種の枚数配列(三麻で存在しない 2m〜8m は常に0)。抜きドラ設定では北(index 30)を別扱い
- 見えていない牌の初期枚数 `u0[k]` = 4(赤込み) − 手牌 − 副露 − ドラ表示牌 − 抜き北(北のみ)。三麻の不在牌は0
- 残りツモ回数 T。状態の残り回数 t(T→0)
- 探索中に追加で抜いた北の枚数 e(0〜北の残り枚数。最大4)
- 13枚の手 H の向聴 s(H)(shanten-dp の値。0=聴牌)

### 3.2 ツモの確率(山の近似)

状態 (H, e) で牌 k を引く確率を `p_k = c_k / Σ_j c_j` とする。次のツモの分布は (H, H0, e) だけで決まる近似で、途中のツモ切りの履歴は反映しない(確定 Q5)。
`c_k = u0[k] − max(0, H[k] − H0[k])`、北は `c_N = u0[N] − max(0,H[N]−H0[N]) − e`。
H0 は**入力の手**(14枚入力なら打牌前の14枚、13枚入力ならその13枚)。打牌候補で捨てた牌は河に出て見えるので山に戻さない。H0 を候補ごとの13枚ではなく入力の手に取ることで、山の確率が打牌候補に依存せず、候補の間で状態の表を共有できる。ツモ切りした牌は山に戻したものとして扱う(他家の行動を無視する一人麻雀で、状態を手牌だけに保つための近似)。赤もこの近似に従う: 赤の五を引いても、手に残さない限り山の赤の枚数 R は減らない(§3.5 の赤の確率はこの前提)。

三麻の牌の上限 `tile_limits`: shanten-dp の `make_tile_limits(true)`(`src/shanten.rs` 181行。35要素で 2m〜8m の index 1〜7 を0、他は4)をそのまま使う。`u0` も2m〜8m は0。これにより2m〜8m は有効牌・待ち・ツモに現れない。1m・9m は存在するので国士の判定には影響しない。

- これは確定1(一人麻雀)の範囲内での山の近似であり、確定(Q5)。代替案は「引いた牌を順に山から除く」厳密化だが、状態に捨て牌の履歴が要り、状態数が爆発するので採らない
- 統計テスト(§9)のモンテカルロは**同じ近似モデル**を模擬する(実装の検証であり、モデルの妥当性検証ではない)。参考として「山を実際に並べて先頭から引く」モンテカルロとの差も測って報告する(合否に使わない)

### 3.3 聴牌前(s ≥ 1)の遷移と方針

1巡:
1. 牌 k を引く(確率 p_k)
2. 抜きドラ設定で k=北 → e+1、同じ巡で再ツモ(残り回数は減らない。補充ツモ)。`c_N` は e の分だけ減るので、北が尽きれば(見えていない北は高々4枚)補充は有限回で終わる
3. 14枚 H+k から打牌 d を選ぶ。打牌後の13枚 H+k−d の向聴 s′ は、1枚の入れ替えなので s−1(前進)・s(維持)・s+1(戻し)のいずれか。どれを候補にするかは §3.6 のオプションで決まる
4. 次状態 (H+k−d, t−1, e)。s′=0 になったら聴牌状態(§3.4)へ

打牌の分類の求め方(shanten-dp の `calc_shanten2` の `discards` は、14枚の最小向聴を達成する打牌だけを返す。実物 `common.rs`):
- 14枚 H+k に1回 `calc_shanten2` を呼び、最小向聴 s14 と `discards` を得る
- s14 = s(前進できないツモ。大半のツモ): `discards` が維持、それ以外の手の牌の種類が戻し(s′ は s+1 しかあり得ない)。追加の計算は不要
- s14 = s−1(有効牌のツモ): `discards` が前進。残りの牌の種類は維持か戻しのどちらかなので、各種類について13枚の向聴を `calc_shanten` で求めて分ける(最大13回)。構成Aでは前進だけを使うので追加の計算は不要
- 計算した13枚の向聴は手のキーでキャッシュする

方針: 各 (H,t,e,k) で、次状態の期待値 EV が最大の d を選ぶ。同値なら和了確率、次に聴牌確率が大きい方、さらに同値なら牌の index が小さい方(決定的にするため)。

### 3.4 聴牌後(s = 0)

- 待ち W(H) は固定(確定2)。門前(副露なし、または暗槓のみ。`hora.ts` 206行の `menzen` 定義と同じ)なら聴牌した打牌で即立直(確定8)
- 1巡: 牌 k を引く。k ∈ W で役あり(§4)なら和了。抜きドラ設定で k=北 のときは次の規則で抜くか和了するかを決める。それ以外(役なしの和了牌を含む)はツモ切りで t−1
- 北の扱い(確定 Q4 の解釈。確定 Q19 案(ii)): 役があって北で和了できるときだけ和了し、それ以外(北が待ちでない、または北待ちでも役がない)は抜いて補充ツモ。現行実装は「北が形として待ちに入っていれば抜かない」なので製造で直す(§11a)
- 結果への影響: 役のない副露の北待ちの手は、(ii) では北を抜いて補充ツモになり、抜きドラと嶺上開花(確定 Q3)で役ありの和了になる道が残る。(i) では北をツモ切りするだけで、その道が無い。役のある手ではどちらも同じ
- 補充ツモで和了したら嶺上開花付き(確定 Q3)
- 聴牌状態の値: 和了確率 P と期待値 EV。`EV = Σ 経路の確率 × 和了価値 V(H, w, e, rinshan)`

### 3.5 和了価値 V(TSで計算する表)

聴牌形 H・和了牌 w・追加抜き北 e・嶺上フラグ r ごとに、赤と裏ドラを平均した受け取り総額:

```
V(H,w,e,r) = Σ_{赤の付き方 ρ} P(ρ) Σ_{裏ドラ飜 j} P_ura(j | H+w, nuki0+e) × best(H+w, ρ, e, r, j)
```

- best: `generateResult` の和了候補のうち `by === 'tsumo'` のものについて、手で加算する抜き北 e' 枚分の飜と裏ドラ j 飜を `yaku` に追加した `Hora` を `calculateHoraScore` に渡し、`payment.total` の最大を取る。役なし(§4)の候補は除く。全候補が役なしなら V=0 として「和了しない」扱い
- 抜き北1枚あたりの加算飜(実物 `hora.ts` 71〜81行 `countDoraHan` は表ドラ分を `nuki × 西の表示牌の枚数` で数え、抜きドラ自体は `nuki-dora` が nuki 飜): 抜きドラ1飜 + 表ドラの西表示牌の枚数 w_d 飜。西表示牌が無ければ +1飜、西1枚なら +2飜。裏ドラ分(西の裏表示牌)は裏ドラ分布の側で数える
- `Input.nuki` と手加算の切り分け(二重加算しない):
  - r=false: `Input.nuki = nuki0`、e' = e
  - r=true: `Input.nuki = nuki0 + 1`、e' = e − 1(r=true は探索中に1枚以上抜いた直後なので e ≥ 1)。嶺上開花の条件は実物で、一般形 `hora.ts` 620行 `(melds に kan あり || input.nuki > 0) && options.rinshan`、七対子等 1057行 `nuki > 0 && options.rinshan` であり、nuki0=0 のとき `Input.nuki = 0` のままでは嶺上開花が付かないため
  - 加算後に最大を取り直すのは、飜の加算で分解ごとの順位が変わり得るため
- 赤 ρ(確定9): 五p・五s それぞれ、最終形の五の枚数 k_f、起点の手の五の枚数 k_0 と赤の枚数 a_0、見えていない五の枚数 N と赤 R から、新たに引いた五 d=max(0,k_f−k_0) 枚のうちの赤の枚数を超幾何分布 Hyp(d; N, R) で列挙する。赤の枚数 = min(k_f, a_0' + 引いた赤)。a_0' = min(a_0, k_f)。打牌で五を捨てるときは赤でない方を先に捨てるとみなす。途中でツモ切りした五は数えない(§3.2 と同じ近似)
- 赤と山の起点の整合(確定 Q20 案a): 山の式(§3.2)は入力の手 H0 を基準にするが、現行の赤の式(red.ts)は k_0・a_0 を打牌候補の手で数える。14枚入力で五を捨てる候補では、山の式では捨てた五の分も引けるのに、赤の式では d = k_f − k_0 > N となって超幾何分布が空になり、到達できる和了の価値が0になり得る。

### 3.6a 状態爆発の原因と案P系の差の上限(第8版。確定 Q14〜Q17)

**実測(製造の停止報告。Worker、各3回冷)**: 案Q の B′ は T=1 で状態 107〜252、T=2 で 3,725〜16,507(3向聴 1,098 ms)。既定(B′+戻し K=2)は T=2 で 14,367〜17,422(1向聴 1,724 ms)。ネイティブ Rust でも B′ 1向聴は T=3 で 62,231 状態・7.2 秒で、1巡ごとに約15〜35倍に増える。構成A(T=18)は完走し、3向聴の中央値 250 ms・最悪 593 ms。

**原因(数理モデル)**: 維持の打牌は「ツモった牌を残し、同じ向聴を保つ別の牌を捨てる」もので、ほぼすべてのツモ(約25種)に対して複数の候補がある。案Q では維持に差の制限が無いので、t 巡後に到達する手は「開始手から最大 t 枚を入れ替えた、向聴 s 以下の手」のほぼ全体になる。開始手から d 枚入れ替えた手の数の上限は C(13,d)×(27種から d 枚の重複組合せ)で、d=1 で約350、d=2 で約3万、d=3 で約100万(上限の目安。向聴の条件で実際はこの一部)。到達集合が T とともに d=T の層まで広がるため、T=18 では状態数が有限の小さな値に収まらない。

**対策の軸(案P系)**: 維持と戻しの打牌に、開始手からの差の上限を課す。前進の打牌は常に許す(聴牌への道を断たない)。上限は「前進した分の差」を差し引いた余裕 M で表す:

`維持・戻しの打牌は diff(H′) ≤ (s_ref − s′) + M のときだけ許す`(s′ は打牌後の向聴、M は0以上の整数)。ツモ切り(H′ = H)は手が変わらないので常に許す

- s_ref(確定 Q18。D-1a(c) の比較の後にオーナーが最終判断): 計算対象の打牌候補(打牌後の向聴が3以下。4向聴になる候補は除外)の13枚の向聴の最大値。13枚入力ならその向聴(= s0)。14枚入力では s0+1 の候補(確定 Q7)を含む最大値で、全候補に共通の1つの値なので、確定 Q10(c)(H0・表を候補で共有)と衝突しない
- s0 を使わず s_ref を使う理由: 14枚入力で打牌後が s0+1 の候補は diff=0 だが、右辺 (s0 − (s0+1)) + M = M−1 は M=0 で負になり、起点で不変条件(右辺 ≥ M ≥ 0)を満たさない(その候補からは維持・戻しができない)。s_ref ≥ 各候補の向聴なので右辺は起点で ≥ M ≥ 0。根拠はこの1点に限る(ツモ切りは常に許すので、s0 基準でも構成A ⊆ B′(M) の包含は崩れない)。代償として、向聴の小さい候補には余裕が最大1枚多く与えられる
- 対案S(Q18 の比較用。測定用の内部フラグ): 基準を候補ごとに、その候補自身の13枚の向聴 s_c とする。実装は TS 側(compute.ts)で打牌候補を s_c ごとに分け(14枚入力で高々 s0 と s0+1 の2グループ)、既存の `search(…, s_ref = s_c)` をグループごとに呼ぶ。探索表は最大2個、聴牌形の評価キャッシュは手牌キーで共有する。Rust 側の状態キーの拡張は不要(状態の表のキーは手牌だけ)。同じ基準の候補どうしでは表を共有でき、確定 Q10(c) は保てる。起点で右辺 = M ≥ 0 なので不変条件も保てる。メリット: 各候補が自分の最短経路に対し同じ M の余裕を持つ(公平)。デメリット: 14枚入力で探索が最大2回(推定で計算量最大2倍)。D-1a(c) で共通 s_ref と比べる。`EngineOptions` とは別の内部フラグ(例 `__experimentalPerCandidateRef`)とし、製品の既定には入れない
- 不採用の対案: 右辺を max(0, s0 − s′) + M とする。起点では破れないが、s0+1 の候補から前進した直後に diff=1 > M(M=0)となり不変条件が保てない。よって採らない

- 不変条件「到達する聴牌前の手はすべて diff(H) ≤ (s_ref − s) + M」の帰納法: 起点は各候補 H で diff=0(14枚入力の候補は H0 の部分集合なので min の和が len(H))、右辺 = s_ref − s + M ≥ M ≥ 0。遷移: ツモ切りは H 不変。前進は diff を最大1増やし右辺も1増える。維持・戻しは条件そのもの。よって**聴牌前の手は、起点との差が `s_ref − 1 + M` 枚以内に収まる**(s ≥ 1 のため)。手の種類はもともと有限なので、これは「到達する手の範囲が巡目とともに広がり続けない」ことを意味する。(H, t) の個数や所要時間まで T に依らないわけではない(DP は T に比例)。DPの状態は (H, t, e) のまま
- 構成Aの打牌(前進・ツモ切り)は常に許されるので A ⊆ B′(M) ⊆ B′+戻し(M)
- M の意味: 前進で得た向聴の改善に対し、余分に許す入れ替えの枚数。M=0 でも維持・戻しは0にならない。例えば2回以上前進した後(s = s_ref−2、d=2)なら、片方の改善だけを取り消す戻し(s′ = s_ref−1、d′=1)は M=0 でも許される(右辺 = 1)。同様に、前進でツモった牌どうしの入れ替え(差が増えない維持)も許される。M=1 は開始手の牌を1枚まで余分に崩せる
- このため後退案(Q16)の(1)「戻しを既定オフ」は M=0 でも意味がある。D-1a で B′(M=0) と B′+戻し(M=0) の状態数・時間の差を測る
- 戻しの打牌も同じ不等式に従う(s′ = s+1 なので、差の余裕が1減る)。案Y(戻した後が3向聴以下)はそのまま適用する
- 14枚入力の到達数: 起点が打牌候補の数(異なる牌の種類、最大14)だけあり、上界は「候補数 × 13枚起点の上界」。13枚起点から d 枚入れ替えた手の数の粗い上界は C(13,d)×C(27+d−1,d)(d=1 で 351、d=2 で 29,484)。実際は向聴の条件と候補の間の重なりで大幅に小さい(推定)
- 3向聴の手の到達数の見積り(推定。未実測): M=0 は構成Aの到達状態(実測 85〜599)に、ツモった牌の差し替えが加わる程度で数倍(数百〜数千)。M=1 は各状態に「開始手の牌1枚を他の牌へ」の分岐(数十)が加わり、数千〜数万。M=2 は数万以上
- 1状態あたりの単価(推定): 製造の B′ T=2 の値(16,507 状態で 1,098 ms、約 65 µs/状態)は探索が主で、DP の巡目数が2しかない。T=18 では DP が状態×T×ツモ種に比例して増え、聴牌形の評価も加わる。構成A(T=18)の実測(3向聴で 85〜599 状態、中央値 250 ms)から逆算すると、単価は**数百 µs〜1 ms 弱**(聴牌形評価込み)。よって 1,000 ms に収まるのは**約千〜数千状態**が目安(推定。根拠は弱い)。M=0 が境界付近、M=1 は超える可能性が高い
- 期待値の単調性: 同じ M のもとでは、候補の集合が A ⊆ B′(M) ⊆ B′+戻し(M) なので A ≤ B′(M) ≤ B′+戻し(M) は保たれる。また M を大きくすると期待値は単調非減少。失われるのは「制限のない B′(第7版の B′)以上」という性質だけである(第7版の B′ は T=18 で計算できないため、比較の相手として実在しない)
- 差の上限を維持にだけ課し戻しには課さない案、戻しにだけ課す案(第7版の案Q)は、どちらも維持が無制限または戻しが無制限になり、到達集合が T とともに増える(戻しは戻した先からまた維持できるため)。よって**維持と戻しの両方に課す**のをとする(確定 Q14)
- 退化特性(数理モデルからの帰結): 13枚換算で s0=1 の手は、M=0 では維持も戻しも起きない(右辺が 1−s′+0 で、維持 s′=1 は diff ≤ 0 = 元の手のみ)。M=1 では維持は起きるが戻しは起きない(戻し s′=2 は diff ≤ 0 で元の手=1向聴と矛盾)。s0=1 で戻しが起きるのは M ≥ 2。M=0 で手替わりが効くのは、s0 ≥ 2 で1回以上前進した後か、14枚入力で s_ref = s0+1 となり向聴の良い候補に余裕が生じる場合
- 既定値(確定 Q15・Q16): 手替わり・向聴戻しとも既定オン。M の範囲は 0〜2。D-1a で開始向聴(1・2・3)ごとに「既定の構成で中央値 ≤ 1,000 ms」を満たす最大の M を報告し、オーナーが既定を決める。既定の M を単一の値にするか開始向聴別にするかも、その時にオーナーが決める(Q15 の枠内。1向聴の M=2 は最大差が2で軽いと見込む。推定)。M=0 でも満たさない場合は §6 の後退案の順で、どこまで下げるかはオーナー判断

}

### 5.3 Rust の公開関数(要点)

- `search(h0: &[u8;34] /*入力の手(§3.2)*/, hands: &[u8] /*打牌候補の列。13枚入力は1件*/, melds_m: usize, u0: &[u8;34], tile_limits: &[u8;35] /*三麻: make_tile_limits(true)*/, nuki_mode: bool, max_draws: u32, tegawari: bool, backtrack: bool, diff_slack: u8, s_ref: i8) -> SearchResult`: 引数の `s0` は廃止し `s_ref` に一本化する。維持・戻しの打牌に `diff(H′) ≤ (s_ref − s′) + diff_slack` を課す(右辺は負になり得るので i16 等の符号付きで計算。旧実装の `max_diff = (s0 as u8).saturating_add(diff_margin)` は置き換える)。BFS は深さ max_draws で打ち切る。全候補から到達する状態を1つの探索表にまとめ、聴牌前の手(向聴≥1)と聴牌形(向聴0)とその待ちを列挙。状態の表のキーは手牌だけ。`m` は 4 − 副露数
- `solve(handle, values: &[f64] /* (聴牌形, 待ち, e, r) ごとの V */) -> Vec<f64>`(全候補を1回で解く)と `solve_for_candidates(handle, values, candidate_indices: &[u32]) -> Vec<f64>`(赤の起点 (k0,a0) が同じ候補の組ごとに呼ぶ): 後退DP(§3.3・3.4)と前進計算(§3.7)。返り値は候補ごとの [tenpai, win, ev, perTurn×3T] の平坦な配列。複数回呼ぶと `policy_discard` が参照する方針表は最後の呼び出しの結果で上書きされる(モンテカルロは対象の組を解いた直後に照会する)
- 打牌候補の生成は `fn discard_candidates(hand, h0, s, s_ref, opts) -> u64`(bitset。WASM 非公開)の1関数に閉じ込め、§3.3 の分類と §3.6・§3.6a の条件で絞る
- `policy_discard(search_handle, hand: &[u8], t: u32, e: u8, draw: u8) -> i8`: `solve` 後に、方針が選ぶ打牌の牌 index(聴牌状態・該当なしは −1)を返す。モンテカルロ(A-5c)が1手ごとに呼ぶ
- 探索の状態は Rust 側に保持し、`search` の戻り値のハンドルで `solve` が参照する(状態を2度渡さない)

## 6. 速度の要件と再測定(確定2・3)

- 比較基準: #137報告 §5 の Worker 案1b(手替わりなし、探索+全評価、冷、手ごとの中央値の中央値): 1向聴 14.5 ms、2向聴 31.2 ms、3向聴 90.8 ms

- 14枚入力では打牌候補(最大14)の到達集合を1つの表で共有するので、候補が増えても重なる部分は1回の計算で済む。対案(候補ごとの開始手。§3.6)を採ると、戻しオン時に最大で候補数倍になる(推定)
- 実測と推定の区別: #137 の実測は構成A(手替わりなし)だけ。B′ と B′+戻しの状態数・時間は**未実測**
- 速度要件の対象は**既定の構成(B′+戻し、M=既定値)**とする。構成A・他の M は比較のための参考値
- 仮の閾値: #137 と同じ「3向聴の全計算が Worker で数百 ms〜1 秒以内」(中央値)。**実挙動未確認**
- 実測済み(第7版の案Q、製造の停止報告): §3.6a の表のとおり。構成A の T=18 は 3向聴の中央値 250 ms(#137 の 90.8 ms の約2.8倍。赤・裏・北・巡目別の評価が加わるため)

- 後退案(確定 Q16。発動はオーナー判断): M=0 でも3向聴の中央値が 1,000 ms を超える場合、(1) 向聴戻しの既定をオフ(B′、M=0)、(2) それでも超えるなら、3向聴のときだけ手替わりを既定オフ(構成A。実測 250 ms で満たす)、の順に下げる。どの段で止めるかは実測値を添えてオーナーに諮る
- 再測定の条件: 既定の構成で3向聴の中央値が 1,000 ms を超えた、またはタブがメモリ不足で落ちた場合は、既定値・M・向聴上限を自分で変えずに製造を止め、測定値を統括へ報告する

## 9. 受け入れ条件

各項目は `npm test`(Vitest)または記載のコマンドで実行する。テストでは `options` を必ず明示する(既定値に依存させない)。構成を指定していない項目は既定の構成(B′+戻し、M=既定値)で計算する。聴牌の起点(A-1・A-2・B 群の多く)は構成によらず同じ値になる(聴牌後は打牌の選択が無い)。手計算の値は設計書の式から求め、テストのコメントに式を書く。GPL実装の出力を期待値に使わない。

### A. 計算の正しさ

- [ ] A-1 聴牌の厳密解(手計算): 共通役牌設定・副露なし・門前。構成 A・B′・既定の3つで計算する。待ち1種、見えていない和了牌 c 枚、見えていない牌の合計 U、q=c/U。§3.2 では和了まで手が変わらず各巡 q なので、T=1・2・18 で `win = 1−(1−q)^T`、巡目別の表は `perTurn[i].win = 1−(1−q)^(i+1)`(i は0始まり)と一致(誤差 1e-12)。`tenpai = 1`、`perTurn[i].tenpai = 1`(3構成とも同じ値)
- [ ] A-2 聴牌の期待値: A-1 の手で、和了価値を `generateResult`(立直・ツモ、裏ドラ表示牌0枚=ドラ表示牌0枚の入力)から求めた値 v として `ev = win × v`(誤差 1e-9)
- [ ] A-3 1向聴の厳密解(構成A): 共通役牌設定・門前・`tegawari:false`。有効牌が1種(c 枚)で、それを引くと必ず同じ聴牌形(待ち1種)になる手を作る。`Mode::all()` では七対子の向聴も最小に混ざり有効牌が1種にならない手があるので、七対子・国士の向聴が一般形より大きいことを確かめた牌姿をテストに明記する。p=c/U、聴牌後の和了確率 q'=c'/U'(c'・U' は有効牌を手に残した後の §3.2 の枚数)。T=2 で
  - `perTurn[0].tenpai = p`、`perTurn[1].tenpai = tenpai = 1−(1−p)^2`
  - `perTurn[0].win = 0`、`perTurn[1].win = win = p×q'`(1巡目に聴牌し2巡目に和了する経路のみ)
  を誤差 1e-12 で検証。(A-3 は構成Aに限る。B′・既定では維持・戻しの経路が加わり手計算の式が変わるため)
