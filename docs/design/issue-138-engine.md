## 1. 前提(数値の意味。UIの注意書きの材料)

- 一人麻雀: 自分のツモだけ。他家の和了・鳴き・流局・他家の捨て牌による山の減少は無視する(確定1)

- 期待値は和了時の受け取り総額(`payment.total`)の期待値で、和了しなかった場合は0として平均したもの

## 3. 数理モデル

### 3.1 記号

- 牌の種類は34種の枚数配列(三麻で存在しない 2m〜8m は常に0)。抜きドラ設定では北(index 30)を別扱い
- 見えていない牌の初期枚数 `u0[k]` = 4(赤込み) − 手牌 − 副露 − ドラ表示牌 − 抜き北(北のみ)。三麻の不在牌は0
- 残りツモ回数 T。状態の残り回数 t(T→0)
- 探索中に追加で抜いた北の枚数 e(0〜北の残り枚数。最大4)
- 13枚の手 H の向聴 s(H)(shanten-dp の値。0=聴牌)

### 3.2 ツモの確率(山の近似)

状態 (H, e) で牌 k を引く確率を `p_k = c_k / Σ_j c_j` とする。
`c_k = u0[k] − max(0, H[k] − H0[k])`、北は `c_N = u0[N] − max(0,H[N]−H0[N]) − e`。
H0 は**入力の手**(14枚入力なら打牌前の14枚、13枚入力ならその13枚)。打牌候補で捨てた牌は河に出て見えるので山に戻さない。H0 を候補ごとの13枚ではなく入力の手に取ることで、山の確率が打牌候補に依存せず、候補の間で状態の表を共有できる。ツモ切りした牌は山に戻したものとして扱う(他家の行動を無視する一人麻雀で、状態を手牌だけに保つための近似)。赤もこの近似に従う: 赤の五を引いても、手に残さない限り山の赤の枚数 R は減らない(§3.5 の赤の確率はこの前提)。

三麻の牌の上限 `tile_limits`: shanten-dp の `make_tile_limits(true)`(`src/shanten.rs` 181行。35要素で 2m〜8m の index 1〜7 を0、他は4)をそのまま使う。`u0` も2m〜8m は0。これにより2m〜8m は有効牌・待ち・ツモに現れない。1m・9m は存在するので国士の判定には影響しない。

- これは確定1(一人麻雀)の範囲内での山の近似であり、確定(Q5)。代替案は「引いた牌を順に山から除く」厳密化だが、状態に捨て牌の履歴が要り、状態数が爆発するので採らない
- 統計テスト(§9)のモンテカルロは**同じ近似モデル**を模擬する(実装の検証であり、モデルの妥当性検証ではない)。参考として「山を実際に並べて先頭から引く」モンテカルロとの差も測って報告する(合否に使わない)

### 3.3 聴牌前(s ≥ 1)の遷移と方針

1巡:
1. 牌 k を引く(確率 p_k)
2. 抜きドラ設定で k=北 → e+1、同じ巡で再ツモ(残り回数は減らない。補充ツモ)
3. 14枚 H+k から打牌 d を選ぶ。打牌後の13枚 H+k−d の向聴 s′ は、1枚の入れ替えなので s−1(前進)・s(維持)・s+1(戻し)のいずれか。どれを候補にするかは §3.6 のオプションで決まる
4. 次状態 (H+k−d, t−1, e)。s′=0 になったら聴牌状態(§3.4)へ

打牌の分類の求め方(shanten-dp の `calc_shanten2` の `discards` は、14枚の最小向聴を達成する打牌だけを返す。実物 `common.rs`):
- 14枚 H+k に1回 `calc_shanten2` を呼び、最小向聴 s14 と `discards` を得る
- s14 = s(前進できないツモ。大半のツモ): `discards` が維持、それ以外の手の牌の種類が戻し(s′ は s+1 しかあり得ない)。追加の計算は不要
- s14 = s−1(有効牌のツモ): `discards` が前進。残りの牌の種類は維持か戻しのどちらかなので、各種類について13枚の向聴を `calc_shanten` で求めて分ける(最大13回)。構成Aでは前進だけを使うので追加の計算は不要
- 計算した13枚の向聴は手のキーでキャッシュする

方針: 各 (H,t,e,k) で、次状態の期待値 EV が最大の d を選ぶ。同値なら和了確率、次に聴牌確率が大きい方、さらに同値なら牌の index が小さい方(決定的にするため)。

### 3.4 聴牌後(s = 0)

- 待ち W(H) は固定(確定2)。門前(副露なし、または暗槓のみ。`hora.ts` 206行の `menzen` 定義と同じ)なら聴牌した打牌で即立直(確定8)
- 1巡: 牌 k を引く。k ∈ W で役あり(§4)なら和了。抜きドラ設定で k=北(かつ北が和了牌でない)なら e+1 で補充ツモ。それ以外(役なしの和了牌を含む)はツモ切りで t−1
- 補充ツモで和了したら嶺上開花付き(確定 Q3)
- 聴牌状態の値: 和了確率 P と期待値 EV。`EV = Σ 経路の確率 × 和了価値 V(H, w, e, rinshan)`

### 3.5 和了価値 V(TSで計算する表)

聴牌形 H・和了牌 w・追加抜き北 e・嶺上フラグ r ごとに、赤と裏ドラを平均した受け取り総額:

```
V(H,w,e,r) = Σ_{赤の付き方 ρ} P(ρ) Σ_{裏ドラ飜 j} P_ura(j | H+w, nuki0+e) × best(H+w, ρ, e, r, j)
```

- best: `generateResult` の和了候補のうち `by === 'tsumo'` のものについて、手で加算する抜き北 e' 枚分の飜と裏ドラ j 飜を `yaku` に追加した `Hora` を `calculateHoraScore` に渡し、`payment.total` の最大を取る。役なし(§4)の候補は除く。全候補が役なしなら V=0 として「和了しない」扱い
- 抜き北1枚あたりの加算飜(実物 `hora.ts` 71〜81行 `countDoraHan` は表ドラ分を `nuki × 西の表示牌の枚数` で数え、抜きドラ自体は `nuki-dora` が nuki 飜): 抜きドラ1飜 + 表ドラの西表示牌の枚数 w_d 飜。西表示牌が無ければ +1飜、西1枚なら +2飜。裏ドラ分(西の裏表示牌)は裏ドラ分布の側で数える
- `Input.nuki` と手加算の切り分け(二重加算しない):
  - r=false: `Input.nuki = nuki0`、e' = e
  - r=true: `Input.nuki = nuki0 + 1`、e' = e − 1(r=true は探索中に1枚以上抜いた直後なので e ≥ 1)。嶺上開花の条件は実物で、一般形 `hora.ts` 620行 `(melds に kan あり || input.nuki > 0) && options.rinshan`、七対子等 1057行 `nuki > 0 && options.rinshan` であり、nuki0=0 のとき `Input.nuki = 0` のままでは嶺上開花が付かないため
  - 加算後に最大を取り直すのは、飜の加算で分解ごとの順位が変わり得るため
- 赤 ρ(確定9): 五p・五s それぞれ、最終形の五の枚数 k_f、起点の手の五の枚数 k_0 と赤の枚数 a_0、見えていない五の枚数 N と赤 R から、新たに引いた五 d=max(0,k_f−k_0) 枚のうちの赤の枚数を超幾何分布 Hyp(d; N, R) で列挙する。赤の枚数 = min(k_f, a_0' + 引いた赤)。a_0' = min(a_0, k_f)。打牌で五を捨てるときは赤でない方を先に捨てるとみなす。途中でツモ切りした五は数えない(§3.2 と同じ近似)
- 裏ドラ(確定8): 裏ドラ表示牌の枚数 = ドラ表示牌の枚数。各表示牌は見えていない牌から独立に1枚(確率 `c_i/Σc`。復元抽出)とする(確定 Q12)。表示牌 i のとき加算飜 = 最終14枚中の `nextIndex(i)` の枚数(+ 次が北なら抜き北 nuki0+e)。表示牌ごとの分布の畳み込み。門前でなければ j=0 のみ
- 評価の単位: `generateResult` の呼び出しは (H, w, ρ, r) ごとに1回(e・j は追加の `calculateHoraScore` だけ)。`HandOptions` は `riichi: 門前なら 'riichi' / それ以外 'none'`、`rinshan: r`、他は false。`Input.nuki` は上の切り分けのとおり、`uradora` は空。`Table` は入力のものを使い、本場・供託は 0 に置き換える(確定 Q6)
- r による役の増加: 嶺上開花の付与は `generateResult` を `rinshan: true` で呼ぶ必要がある(役の有無が変わるため、飜の加算で代用しない)。よって (H,w,ρ) ごとに r=false と、抜きドラ設定で山に北が残るとき r=true の最大2回呼ぶ

| X(不採用) | 戻しの打牌は `s′ ≤ s0` | 効かない(s<s0 のときしか戻せない) | 状態の増加が小さい | s0=1 で無効。s0=2 でも聴牌に T≥4、和了に T≥5 が要る |

(2) 差の条件をどの打牌に課すか(2案。K は差の余裕。既定 K=2。確定 Q11):

| 案 | 内容 | 到達する手 | 単調性 A ≤ B′ ≤ B′+戻し | 性質 |
| --- | --- | --- | --- | --- |
| Q(採用) | `diff(H′) ≤ s0 + K` を**戻しの打牌だけ**に課す。前進・維持は B′ と同じく無制限 | B′ で到達する手の全体 + そこから戻した手(差 ≤ s0+K)とその先 | 成り立つ(候補が B′ の上位集合) | 維持を重ねて差が s0+K を超えると、以後の戻しは差が減るまで使えない。回数では禁止しないが、差によって実質的に戻しの機会が絞られる |
| P(不採用) | `diff(H′) ≤ s0 + K` を**維持と戻しの打牌**に課す(前進は常に可。聴牌に至る道を断たないため) | 向聴1以上の手は差 ≤ s0+K+(前進の回数 ≤ 3) の範囲に収まる | 成り立たない(B′+戻し では維持が制限されるため、B′ より ev が小さくなり得る) | 到達範囲がはっきり有限で、状態数の見積もりがしやすい |

- 聴牌(s=0)からの戻しは、待ち固定(確定2)によりどの案でも不可
- 「一度使ったら以後は禁止」としない: どの案も条件は H′・現在の向聴・H0 だけで決まり、戻しの回数を数えない
- 状態の表: 条件が H0・s0 に依存するが、§3.2 のとおり H0 を入力の手に取る(確定 Q10)ので、14枚入力の打牌候補の間でも条件は共通。**DPの状態は (H, t, e) のままで、候補の間で表を共有する**
- 状態数(推定。未実測): 案Q では B′ の到達集合に、戻しで生じる向聴 s+1 の手とその先が加わる。戻し先は1手あたり最大13種で、差の条件で絞られる。B′ の数倍(推定)。案P はそれより少ないが B′ 部分も縮む
- K=2 の根拠(推定): 戻しは有効な牌を1枚捨て、別の牌を入れて前進し直すので、1回の戻しを生かすのに最短経路より約2枚多い入れ替えが要る。K=2 は「最短経路+戻し1回分」の余裕に相当する。T=18 に対し3向聴の最短の前進は3回で、残りの巡目で受け入れの広い形へ組み替える余地がある。K を上げると到達する手は組合せ的に増える(推定)。速度の上限は §6 の閾値とし、D-1 で K=2 が収まらなければ、K を自分で変えずに報告する
- 立直後(確定8・2a): 門前で聴牌したら即立直なので、聴牌の時点で手替わり・戻しとも終わる。副露の聴牌も確定2(待ち固定)で同じ。したがって「立直後は許さない」は、聴牌状態(§3.4)の遷移に打牌の選択が無いことで満たされ、追加の条件は要らない
- 単調性(数理モデルからの帰結): 候補の集合は A ⊆ B′ ⊆ B′+戻し なので、期待値の最大値は A ≤ B′ ≤ B′+戻し(和了確率・聴牌確率は単調とは限らない)(案Q のとき。案P では成り立たない)。案Xでは s0=1 のとき B′ と B′+戻しは同値

### 5.3 Rust の公開関数(要点)

- `search(h0: &[u8;34] /*入力の手(§3.2)*/, s0: i8, hands: &[u8] /*13×34 の打牌候補の列。13枚入力は1件*/, melds_m: usize, u0: &[u8;34], tile_limits: &[u8;35] /*三麻: 2m〜8m を0(§3.2)*/, nuki_mode: bool, max_draws: u32, tegawari: bool, backtrack: bool, diff_margin: u8) -> SearchResult`: 全候補から §3.6 の打牌候補で到達する13枚の状態を1つの表にまとめ(候補の間で共有)、(向聴≥1)と聴牌形(向聴0)とその待ちを列挙。状態は34バイトのキーでハッシュ化。`m` は 4 − 副露数
- `solve(search_handle, values: &[f64] /* (聴牌形, 待ち, e, r) ごとの V */) -> Vec<f64>`: 後退DP(§3.3・3.4)と前進計算(§3.7)。返り値は候補ごとの [tenpai, win, ev, perTurn×3T] の平坦な配列

- `policy_discard(search_handle, hand: &[u8], t: u32, e: u8, draw: u8) -> i8`: `solve` 後に、方針が選ぶ打牌の牌 index(聴牌状態・該当なしは −1)を返す。モンテカルロ(A-5c)が1手ごとに呼ぶ
- 探索の状態は Rust 側に保持し、`search` の戻り値のハンドルで `solve` が参照する(状態を2度渡さない)

### A. 計算の正しさ

- [ ] A-1 聴牌の厳密解(手計算): 共通役牌設定・副露なし・門前。構成 A・B′・既定の3つで計算する。待ち1種、見えていない和了牌 c 枚、見えていない牌の合計 U、q=c/U。§3.2 では和了まで手が変わらず各巡 q なので、T=1・2・18 で `win = 1−(1−q)^T`、巡目別の表は `perTurn[i].win = 1−(1−q)^(i+1)`(i は0始まり)と一致(誤差 1e-12)。`tenpai = 1`、`perTurn[i].tenpai = 1`(3構成とも同じ値)
- [ ] A-2 聴牌の期待値: A-1 の手で、和了価値を `generateResult`(立直・ツモ、裏ドラ表示牌0枚=ドラ表示牌0枚の入力)から求めた値 v として `ev = win × v`(誤差 1e-9)
- [ ] A-3 1向聴の厳密解(構成A): 共通役牌設定・門前・`tegawari:false`。有効牌が1種(c 枚)で、それを引くと必ず同じ聴牌形(待ち1種)になる手を作る。`Mode::all()` では七対子の向聴も最小に混ざり有効牌が1種にならない手があるので、七対子・国士の向聴が一般形より大きいことを確かめた牌姿をテストに明記する。p=c/U、聴牌後の和了確率 q'=c'/U'(c'・U' は有効牌を手に残した後の §3.2 の枚数)。T=2 で
