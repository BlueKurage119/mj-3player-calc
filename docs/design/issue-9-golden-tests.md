## 3. 検証方法(テストから見た API)

1ケースにつき次を行う。

1. `input.hand` に14枚(副露がある場合は残りの手牌。末尾が和了牌)を、`input.melds` に副露を、`input.dora` にドラ表示牌を渡して `generateResult` を呼ぶ
2. 戻り値が `hora-shanten`/`hora` であることを確認し、`hora` から `by`(`'ron'`/`'tsumo'`)が一致する1件を取り出す
3. 次を期待値と比較する
   - **役**: `yaku` を `name` → 飜数(役満は `point`)の対応にした集合。順序は比較しない(`toEqual` にソート済み配列を渡す)
   - **飜**: 通常役の `han` 合計
   - **符**: `type: 'mentsu'` のときは `ceil10(sumOfFu(fu))`、`type: 'chitoitsu'` のときは 25。期待値は画面の符(切り上げ後)
   - **基本点**: 通常役は `calculateBasePoint(符, 飜, false, true)`、役満は `8000 × point 合計`
   - **区分**: 基本点から `'通常' | '満貫' | '跳満' | '倍満' | '三倍満' | '役満'` を導き(数え役満は `'役満'` で、役が通常役のみのもの)、期待値と比較する
4. 期待値の基本点は、ケースの飜・符から**テスト内でも計算しない**。Wikipedia の式で手計算した数値をデータに直接書く(実装の式で期待値を作ると独立性がなくなるため)

### 3.1 固定する条件(三麻化で変わらない層に限定するため)

| 項目 | 固定値 | 理由 |
| --- | --- | --- |
| `Table.round` | `'east'` または `'south'` | 北を場風にしない |
| `Table.seat` | `'east'`・`'south'`・`'west'` のいずれか | 北家は三麻に存在しない。北を自風にしない |
| `Table.continue` / `deposit` | 0 | 本場・供託は固定対象外 |
| `Rule.red` | `{ m: 0, p: 1, s: 1 }` | 仕様§1の所定値(5p・5s 各1枚)。赤5mは三麻に存在しない |
| `Rule.honbaBonus` | `100` | 本場は基本点に影響しない。型を満たすための値(`Table.continue = 0` でもある) |
| `Rule.roundedMangan` | `false` | 仕様§3.3の所定値(切り上げ満貫なし) |
| `Rule.doubleWindFu` | `4` | 連風牌(ダブ東・ダブ南)の雀頭を含むケースを作らないため、基本点に影響しない。型を満たすための値。連風牌の雀頭は §5.3 のデータ検査で禁止する |
| `Rule.accumlatedYakuman` | `true` | 仕様§3.3の所定値(数え役満あり) |
| `Rule.multipleYakuman` | `true` | 仕様§3.3「役満の複合を認める」 |
| `Rule.kokushi13DoubleYakuman` | `true` | 仕様§3.3 ダブル役満の対象(国士無双十三面待ち) |
| `Rule.suankoTankiDoubleYakuman` | `true` | 同(四暗刻単騎) |
| `Rule.daisushiDoubleYakuman` | `true` | 同(大四喜。ただし北を使うためケースには入らない) |
| `Rule.pureChurenDoubleYakuman` | `true` | 同(純正九蓮宝燈) |

`src/` に既定の `Rule` 値は無い(`rule.ts` は型と比較関数のみ)ため、上記をテスト内の定数として全フィールド明示で定義する。
| `HandOptions` | `riichi` だけをケースごとに指定する。`GoldenCase.riichi`(`'none' \| 'riichi' \| 'double-riichi'`)を変換せずそのまま渡す。`ippatsu`・`rinshan`・`chankan`・`haitei`・`tenho` は `false` | 偶然役は画面とのずれが出やすく、三麻固有の扱い(抜き後の嶺上等)もあるため。ダブル立直(2飜)は三麻・四麻共通の層なので対象に含める【確定】 |

## 4. 三麻化で結果が変わりうる要素と方針

2m〜8m を含まない牌姿でも、次の要素は三麻化で結果が変わる。

| 要素 | 四麻コアの現挙動 | 三麻での挙動 | 方針 |
| --- | --- | --- | --- |
| ドラ表示牌 `1m` | ドラ `2m` | ドラ `9m` | **ドラ表示牌に `1m` を使わない**(データ検査で保証)。`9m→1m` は両者共通なので使ってよい |
| 北の刻子・槓子 | 客風(場風・自風が北でなければ役なし) | 共通役牌設定では「役牌：北」1飜、抜きドラ設定では客風 | **北の刻子・槓子を含むケースを入れない**。北の雀頭(客風=0符)も設定で符が変わる(共通役牌では2符)ため**入れない** |
| 北家・北場 | 北が自風・場風になりうる | 北家は存在しない | §3.1 のとおり席・場を固定 |
| 抜きドラ | なし | 1枚1飜 | 抜き北を含む和了の扱いは §5.4 |
| 赤5m | `Rule.red.m` で有効 | 存在しない | `red.m = 0`、赤5mを使わない |
| チー | 可能 | 存在しない | **チーを含むケースを入れない**(喰い平和形は 1m・9m を含まない順子が必要だが、チーを使わずポン・明槓で作る) |
| ツモの点数配分・ツモ損 | 四麻配分 | 三麻配分 | 支払いは固定対象外(A5で置き換え) |
| 天和・地和 | `seat` で分岐 | 同じ | 偶然役は扱わない |

### 5.2 ケースの型(製造担当はこのとおりに作る)

```ts
export interface GoldenCase {
  id: string;                 // 例: 'G01'。収集リスト(§7)の番号と一致させる
  category: 'C1' | 'C2' | 'C3' | 'C4' | 'C5' | 'C6' | 'C7' | 'C8' | 'C9' | 'C10' | 'C11'; // §6 のカテゴリ
  title: string;              // 日本語のテスト名。例: '平和ツモ 20符'

  dora: string;               // ドラ表示牌(MPSZ表記)。無ければ ''
  by: 'ron' | 'tsumo';
  riichi: 'none' | 'riichi' | 'double-riichi'; // HandOptions.riichi にそのまま渡す
  seat: 'east' | 'south' | 'west';
  round: 'east' | 'south';
  expected: {
    yaku: Record<string, number>; // 役名(yaku.ts の name)→ 飜数(役満は倍数)
    han: number;                  // 通常役の飜合計(役満のみのケースは 0)
    fu: number | null;            // 切り上げ後の符。役満・国士は null
    basePoint: number;            // Wikipedia の式で手計算した基本点
    tier: '通常' | '満貫' | '跳満' | '倍満' | '三倍満' | '役満';
  };
  source: {
    yakuHanFu: string;  // 例: '雀魂 和了画面まとめ ../../../doc/golden/cases.csv G01' / 'Wikipedia 符計算例' 等
    screenshot?: string; // 裏付けのスクリーンショット(任意)。例: '../../../doc/golden/screenshots/G01.png'
    basePoint: string;  // 'Wikipedia「麻雀の得点計算」(基本点=符×2^(飜+2)、満貫以上の区分)'
    verifiedBy: ('screenshot' | 'hand-calc' | 'kobalab')[]; // 検算に使った手段(§5.5)。2つ以上
    nukiDoraDeducted?: number; // 画面の飜から差し引いた抜きドラの飜数。抜き北なしなら省略

```

- 出典はデータの `source` に残し、テストファイル冒頭にも出典の説明をコメントで書く(業務標準07)
- 出典の参照は相対パスのみ。絶対パス・ホームディレクトリ名を書かない(AGENTS.md 3.1-1)
- 画面の裏ドラは、コアに専用の役名が無いため**表ドラと合算して `dora` の飜に入れる**(例: 表ドラ1・裏ドラ2 → `dora: 3`)。裏ドラ表示牌は `dora` 表示牌の文字列に加える。裏ドラを含む和了の収録は認める【確定】

### 5.3 データ検査テスト(ケースの前提を機械的に保証)

`golden.test.ts` に、全ケースについて次を確かめる `describe` を置く。

1. 手牌・副露・ドラ表示牌に `2m`〜`8m` が無い
2. ドラ表示牌に `1m` が無い
3. 北(`4z`)が手牌・副露に無い
4. 副露に `chii` が無い、赤5m(`0m`)が無い
5. `seat` / `round` に `'north'` が無い。連風牌(`round` と `seat` が同じ風)の雀頭を含まない
6. `source.yakuHanFu` と `source.basePoint` が空でない
7. `id` が重複しない、ケース数が 20 以上 30 以下

### 5.4 抜き北を含む和了の扱い 【確定】

雀魂の三麻で集めた和了には抜き北が付くことがある。**抜き北を含む和了も、抜きドラの飜を差し引いて収録する(案B)。** オーナーが和了画面をスプレッドシートにまとめ、差し引きと検算を済ませたものを提示する。スプレッドシートを正の出典とし、スクリーンショットは裏付けとして任意で添える。

- 手牌は抜き北なしの形としてそのまま入力する
- 差し引いた飜数を `source.nukiDoraDeducted` に必ず記す(期待値の飜・基本点・区分は差し引き後の値)
- 差し引き後の飜で満貫等の区分が変わりうるため、画面の点数表示は使わない

(検討時の選択肢: 案A 収録しない/案B 差し引いて収録。案Bに確定)

なお抜き北の有無によらず、雀魂三麻の画面に出る役・飜・符は四麻コアと一致するはず(§4 の要素を避けているため)。点数表示はツモ損を含むので使わない。

### 5.5 検算の方法 【確定】

期待値の役・飜・符は、次の3つの手段のうち**2つ以上で一致を確かめたもの**とする。

| 手段 | `verifiedBy` の値 | 内容 |
| --- | --- | --- |
| 和了画面 | `'screenshot'` | 雀魂または麻雀一番街の和了画面のスクリーンショット |
| 手計算 | `'hand-calc'` | Wikipedia「麻雀の得点計算」に基づく手計算 |
| 電脳麻将 | `'kobalab'` | kobalab の電脳麻将の和了点計算(https://kobalab.net/majiang/hule.html)。livewing/mahjong-calc とは別の実装 |

- livewing/mahjong-calc(本リポジトリの計算コアの取り込み元)は**テストの対象の実装なので検算に使わない**。本リポジトリのアプリ画面も同様に使わない
- 使った手段を `source.verifiedBy` に配列で記録する(cases.csv では `verifiedBy` 列に `screenshot+kobalab` のように `+` 区切りで書く)
- 抜き北を差し引いたケースは、差し引き後の飜を各手段で突き合わせる(電脳麻将・手計算には抜き北なしの形で入力する)
