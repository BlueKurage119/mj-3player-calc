# 要件(協議記録)

更新日: 2026-10-20(ルール仕様を分離)

確度のタグ: 【確定】オーナーと合意済み ／ 【設計案】統括担当の提案で未合意 ／ 【未確定】未決(着手前にヒアリングする)

## 1. 概要

- 【確定】三人麻雀に特化したスマホ向け点数計算機。Webアプリ(PWA)として配布し、オフラインでも全機能が動く
- 【確定】開発環境は React + Vite(TypeScript)
- 【確定】ライセンスは MIT。計算コアは livewing/mahjong-calc(MIT)から取り込む([license-policy.md](license-policy.md))
- 【確定】Version 1 のリリースを優先する。何切るの期待値計算(Epic F のフェーズ2)は v1 の後に回す

## 3. 機能要件

### 3.1 手牌の入力
- 【確定】パレット方式とテンキー方式(mj-mighty-calc 式)を併用する。切り替えても入力中の手牌は消えない
- 【確定】三麻で使わない牌(2m〜8m)は入力できない。同じ牌の5枚目は入力できない(赤牌を含めた枚数を管理する)
- 【確定】副露はポン・明槓・暗槓・加槓(チーはない)
- 【確定】抜き北の枚数入力(北の扱いが「抜きドラ」のときのみ)
- 【確定】ドラ表示牌・裏ドラ表示牌。萬子は 1m→9m、9m→1m とめくる
- 【設計案】和了牌は、手牌の最後の牌として指定する(mahjong-calc の方式)

### 3.2 状況の入力
- 【確定】自風は東・南・西のみ。場風、親か子か、ツモかロン
- 【確定】立直、ダブル立直、一発、嶺上開花、槍槓、海底、河底、天和、地和
- 【確定】本場・供託。三麻の1本場あたりの点数は設定値にする

### 3.3 結果表示
| 牌姿 | 表示する内容 |
| --- | --- |
| 和了形 | 【確定】役一覧、翻・符、符の内訳、点数、ツモ時の支払いの内訳 |
| 聴牌形 | 【確定】待ち牌ごとの役と打点(ツモとロン)、残り枚数 |
| それ以外 | 【確定】向聴数、有効牌の種類と枚数、何切る |

### 3.4 何切る
- 【確定】フェーズ1(v1): 打牌候補ごとに向聴数、受け入れの種類と枚数を表示する。残り枚数は三麻の牌構成(108枚)と抜き北を前提にする
- 【確定】フェーズ2(v1 の後): 聴牌確率・和了確率・期待値。Web Worker で計算する。クリーンルームで独自実装する

### 3.5 ルール設定
| 項目 | 選択肢 |
| --- | --- |
| 赤ドラ | 【確定】赤なし／2枚(基準。5p・5s 各1)／4枚(5p・5s 各2)。全赤は採用しない |
| 数え役満 | 【確定】あり(基準)／なし |
| 切り上げ満貫 | 【確定】なし(基準)／あり |
| ツモ損 | 【確定】あり(基準)／北家分折半／ロン打点折半。【未確定】端数処理 |
| 北の扱い | 【確定】抜きドラ(基準)／共通役牌 |
| その他 | ルールの詳細は [麻雀ルール仕様](mahjong-rules.md) を正本とする |

- 【確定】ルールは柔軟に切り替えられるようにする
- 【設計案】よく使う組み合わせを名前付きのプリセットとして保存できる
- 【確定】設定は端末に保存する

## 4. 非機能要件

- 【確定】デザインは Material Design 3 Expressive に準ずる。Material Web で使えるものはラップ・改造して使い、使えない部分は自作する
- 【確定】PWA(vite-plugin-pwa)。WASM と牌画像もプリキャッシュする
- 【設計案】点数計算は入力後すぐ(100ms 以内)に表示する
- 【設計案】タップ領域は 48dp 以上。入力部分を画面下半分に置き、片手で操作できるようにする
- 【確定】品質チェックは Biome(lint・format)、tsc(型検査)、Vitest(テスト)。GitHub Actions の CI で実行する
- 【設計案】点数・役・符はゴールデンテスト(出典付きの期待値)で担保する。取り込んだ mahjong-calc はテストが牌ユーティリティのみのため、改修前に整備する

## 5. 既知の改修ポイント(調査済み)

- 【確定】手牌分解器(Rust)は34種の枚数配列を受け取るだけで、牌の種類を知らない。2m〜8m を0枚にすれば無改修で三麻の手牌を分解できる(テストで確認済み)。ただし入力を検証しないため、牌セットの保証は TS 側の責任
- 【確定】`shantenTiles`(浮き牌の前後2枚)と`chitoitsuShantenTiles`(34種を列挙)は、2m〜8m を有効牌に含めてしまう。除外が必要
- 【確定】四麻前提の箇所: 自風に北家がある、支払い計算が4人払い前提、残り枚数が全種類4枚前提、ドラ表示牌の「次の牌」
- 【確定】mahjong-calc の localStorage 復元にはマイグレーションがない。Rule・Input を拡張するときに対応が必要
