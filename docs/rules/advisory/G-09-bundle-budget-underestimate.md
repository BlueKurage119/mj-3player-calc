# バンドルサイズの見積り不足

対象: 設計担当(バンドルの増分を積算する場合)。**必須事項(目標値の扱い・基準値の実測・PR記載)は[09-bundle-budget-protocol.md](../09-bundle-budget-protocol.md)を参照。** 本書は積算のコツである。**必須の技術制約(sideEffects・パッケージ固定等)は[06-ui-md3-protocol.md](../06-ui-md3-protocol.md)を参照。**

**出典: `mj-stats-viewer`での差し戻し事例(4回連続で予算超過)。** 設計時にバンドルサイズの増分を見積もる場合、「UIコンポーネントを1つ置いただけの簡易プローブ」の実測値をそのまま枠にしない。フル実装が持ち込む重さ(型定義・状態分岐・アクセシビリティラベル・null安全化・ドメイン層の追加)を勘定に入れ、**簡易プローブの実測値のおおむね3倍**を目標値(積算の上限の目安)にする。

実測が目標値を超えた場合は「収まらなかった」と即断せず、意図しない取り込み(未使用コンポーネント・devコード・ライブラリ全量 import等)が無いかを先に実測してから報告する。

見積りの手順: ①`main`の実測を基準値とする。②導入する部品・依存を1つずつ足したビルドの増分を実測する(使わなかったコードが全量 import 等で混入していないかも、このときに分かる)。③実測の合計に余裕(実装が持ち込む分)を見て、目標値とする。
