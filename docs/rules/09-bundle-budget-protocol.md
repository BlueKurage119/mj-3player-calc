# バンドル目標値業務標準

対象: 初回 JS(`dist/index.html` から読み込まれる JS)に影響する変更を含む Issue のすべてのフェーズ。試算のコツ・過去事例は[G-09-bundle-budget-underestimate.md](advisory/G-09-bundle-budget-underestimate.md)を参照。

## 位置づけ

- 初回 JS のサイズは**目標値**として扱う。絶対値の上限は置かない。目標値の超過を理由に、検収を不合格にしない。
- 歯止めは、設計時の積算と、検収時の実測・報告で効かせる。「必要な分だけ増やし、不要なものを組み込まない」ことを確かめるのが目的である。
- 本標準が置かれる前の設計書にある「≤ 102,000 B」などの絶対値は、本標準に基づく目標値として扱い、不合格条件にしない。

## 計測方法

`npm run build` の後、`dist/index.html` の `<script type="module" src>` と `<link rel="modulepreload" href>` が指す JS をそれぞれ `gzip -9 -c <file> | wc -c` で測り、合計する。記録の単位は B とする(kB の併記は可)。遅延読み込みのチャンク・WASM・SVG 等は合計に含めない。それらに影響する変更があるとき、または設計書で指定されたときは、別に実測して記録する。

## 必須事項

### 設計

1. 設計時に、基準値(`main` の初回 JS の合計。計測方法は上記)を実測し、設計書に書く。実測できないときは、できない理由と「実挙動未確認」を書く。
2. 増分の見込みを積算し、設計書に内訳を書く。新規の部品・依存を導入するときは、導入前に実測して根拠にする。
3. 設計書に「基準値 + 積算した増分」を目標値として書く。受け入れ条件には、実測値の記録を含める。目標値の超過を不合格条件にしてはならない。
4. 不要な取り込み(ライブラリの全量 import、dev 専用コード、使わない部品)を避ける。避けられない増分は、積算の内訳にその理由を書く。

### 製造・検収

5. ビルド後に初回 JS の合計を実測し、基準値との差を求める。
6. 実測値が目標値を超えたときは、「収まらなかった」と即断せず、意図しない取り込みがないかを先に調べ、見つかった場合は除去する(4)。
7. 製造担当の最終報告と、検収担当が作成する PR 本文に次を書く: 基準値、実測値、増分、積算した増分との差、超過した場合の超過量と原因。

### 基準値の更新

8. マージ後は、その Issue の実測値が次の基準値になる。
